* Understand what this course is about

- This is what the *course catalog* says:
  #+begin_quote
  "This course is a continuation of *Computer Science II* and provides a
  deeper look into *object oriented programming*, generic *types*, *lambda*
  functions, *stream( processing, and *concurrent* processing. It also
  presents several basic *data structures*: stacks, queues, lists,
  trees, and graphs. *Algorithms* for sorting, searching, and memory
  management are also introduced."
  #+end_quote

- *Prerequisite*: COSC 1220 Computer Science II
  #+begin_quote
  "A broadening of foundations for computer science with advanced
  concepts in software engineering and program development. Topics
  include an introduction to *data structures*, *analysis of algorithms*,
  and *object-oriented design*."
  #+end_quote

- What you should already know (concepts/theory):
  #+begin_quote
  - Program structure and the compile/run model (~javac/java~)
  - Primitive types, expressions, casting
  - Conditionals and loops (~if~, ~while~, ~for~, nesting)
  - Arrays
  - Standard I/O (~StdIn/StdOut/StdDraw~)
  - Simulation / Monte Carlo style programs
  - Markov chains / transition matrices
  - Function definition, parameters, return values, ~static~ methods
  - Modular decomposition (libraries vs. clients)
  - Recursion (base case, recursive case, call stack)
  - Encapsulation (fields + methods, constructors)
  - API design (exposed vs. hidden state)
  - Instance methods vs. ~static~ methods
  - Reference types vs. primitives
  - Aliasing and mutability
  - Defensive copies
  - Using existing data types
  - Creating custom data types
  - Designing (well-formed) data types
  - Composing multiple types into a larger program
  #+end_quote

- What you should already be able to code:
  #+begin_quote
  Design, implement and test a simply abstract data type that you can
  use to model a real time object - for example a stopwatch to compare
  running times of performance-critical methods.
  #+end_quote

- What you will add in this class:
  #+begin_quote
  You will learn to "pay attention to the cost" of your code. You will
  build linked structures that can be arbitrarily complex. With
  these, and with arrays, you can build *data structures*
  #+end_quote

- This is what the course is really about:
  #+begin_quote
  1. Learn how to tell a machine what to do safely, clearly, and in a
     way other programmers can trust and build on.
  2. Learn how to write programs that work, scale and perform.
  3. Learn to use the computer as a tool for bigger and messier jobs.
  #+end_quote

- How can you get it if you don't have it yet?
  #+begin_quote
  On your own machine, install *Amazon Corretto OpenJDK 17*
  ([[https://aws.amazon.com/corretto/][aws.amazon.com/corretto]]) so your code behaves the same way in and
  out of class. It's free, and installers exist for Windows, macOS,
  and Linux. In the course I'll occasionally switch to a newer JDK for
  one specific demo, but 17 is the baseline for everything you turn
  in.
  #+end_quote

- What else do you need?
  #+begin_quote
  *An editor or IDE* - your choice, entirely. VS Code, IntelliJ,
  Notepad++, vim, Emacs, whatever you're comfortable with or want to
  learn. I won't teach or require any particular one.

  What I *will* require: you compile and run every program by hand on
  the command line (~javac~, then ~java~), not by clicking an IDE's "Run"
  button. IDEs hide that step - and understanding what ~javac~ and ~java~
  each do, separately, is one of the things this course actually
  teaches. Use an IDE for editing if you like it; just don't let it
  run your code for you.
  #+end_quote

- How will you run commands (compile, run, navigate files)?
  #+begin_quote
  You need a *terminal* / *shell* / *CLI* you're comfortable with[fn:2]:

  - *Windows*: install [[https://gitforwindows.org/][Git Bash]] - gives you a Unix-like shell, which
    matches how I'll demo things in class and how the instructions in
    this course are written.
  - *macOS*: the built-in *Terminal* app works out of the box.
  - *Linux*: whatever shell you already have.

  "It works on my machine" is the most common failure mode - if your
  setup doesn't match one of the above, come to office hours *before*
  the first assignment is due, not after.
  #+end_quote

- What else would be cool?
  #+begin_quote
  Nothing here is required - just worth knowing about if you want to
  go further:

  - *A real debugger* instead of scattering ~println~ everywhere: step
    through execution line-by-line, inspect variables, set
    breakpoints. Most IDEs ship one built-in (VS Code's Java
    extension, IntelliJ), or use ~jdb~ straight from the command line
    - same JDK you already installed. This doesn't conflict with the
    hand-compile requirement: you're still running ~javac~ yourself,
    just attaching a debugger to watch it run instead of only reading
    ~stdout~.
    
  - *Linux*, if you're on Windows and want more than Git Bash gives you:
    install WSL (Windows Subsystem for Linux) for a real Linux
    environment side-by-side with Windows, free. 
  #+end_quote

* Glossary

** Programming concepts

| Term                       | Definition                                   |
|----------------------------+----------------------------------------------|
| Aliasing                   | Two variables referencing the same object    |
| API                        | Methods a class exposes to its users         |
| Concurrent processing      | Running tasks whose execution overlaps       |
| Defensive copy             | Copy made so edits don't affect original     |
| Encapsulation              | Bundling data with the methods on it         |
| Generic type               | Class/method written to work with any type   |
| Graph                      | Nodes/edges; multiple parents, cycles OK     |
| IMRaD                      | Intro, Method, Results, and Discussion       |
| Instance vs. static method | Object method vs. class-level method         |
| Lambda function            | Short unnamed function used as a value       |
| List                       | Ordered sequence of elements                 |
| Markov chain               | Next state depends only on current one       |
| Memory management          | Allocating/freeing memory at runtime         |
| Monte Carlo method         | Estimating results via random sampling       |
| Mutability                 | Whether an object's state can change         |
| OOP                        | Code organized around objects (data+methods) |
| Queue                      | First in, first out data structure           |
| Reference type             | Stores an object's location, not its value   |
| Searching                  | Finding whether/where a value occurs         |
| Sorting                    | Arranging elements into a defined order      |
| Sprint                     | Short work cycle ending in a Scrum review    |
| Stack                      | Last in, first out data structure            |
| Stream processing          | Data as a pipeline: filter, map, reduce      |
| Transition matrix          | Probabilities of moving between states       |
| Tree                       | Nodes with at most one parent, no cycles     |
