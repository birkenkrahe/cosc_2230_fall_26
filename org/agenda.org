1) Remember at least one "illusion" that the machine presents to the

   #+begin_quote

   #+begin_quote
   1. Stack (grows down) -> Stack overflow

   #+end_quote

   #+begin_quote
   - A janitor for the *heap* only.
   - when an object's life cycle ends, GC sweeps and reclaims memory
   - Automatic in Java/Python but matters for speed
   - Manual in C/C++ ~malloc~
   #+end_quote

5) What are three lenses on OOP?
   #+begin_quote
   1) Everything is an object (can become a reference type)
   2) Objects send message to each other (via their APIs)
   3) An object is a state (classes have "memory" and their methods
      manipulate the state)
   #+end_quote

6) Do you ever hold an object itself in Java, or only a reference to it?
   #+begin_quote
   For a *reference type* (any ~class~, array, or ~String~) you only ever
   hold a *reference* to the object on the heap -- assignment and method
   calls copy the reference, not the object.

   The 8 *primitive* types (~byte~, ~short~, ~int~, ~long~, ~float~,
   ~double~, ~char~, ~boolean~) are the exception: a primitive variable
   holds the *value* directly and is copied by value. There is no
   reference.
   #+end_quote

** Review (Sept 4 video)

1) Why compare the =Greeting= class across Java, C++ and Python at all?
   #+begin_quote
   Algorithms and data structures are *language-agnostic*. You learn
   DS&A first, then pick the language that best supports your solution
   path. All high-level languages share the basics (e.g. arrays), but
   not the same data structures, and they implement them differently:
   a resizable array is ~std::vector~ in C++ and ~ArrayList~ in Java --
   the same data structure, but different implementations and semantics
   (value vs. reference).
   #+end_quote

2) What does Java give you for free that C++ makes you set up
   explicitly?
   #+begin_quote
   In C++ you ~#include~ a library for I/O and one for strings; the
   standard string is ~std::string~ (namespace prefix); and there is no
   ~println~ -- output goes through ~std::cout~, an ~ostream~ object.
   Access defaults differ too: a C++ ~class~ has no keyword on the class
   itself, and its members default to ~private~ (C's ~struct~ is ~public~).
   #+end_quote

3) How many ~main~ functions can a C++ program have, and what is the
   full signature?
   #+begin_quote
   Exactly one ~main~ for the whole program, however many files there
   are. Full form: ~int main(int argc, char *argv[])~ -- ~argc~ is the
   argument count, ~argv~ is an array of C-string (~char *~) pointers,
   and ~argv[0]~ is the program name.
   #+end_quote

4) Python is "interpreted" -- how is it still like Java under the hood,
   and how is it different?
   #+begin_quote
   Like Java: CPython compiles the source to byte code that a virtual
   machine interprets. Unlike Java: no type checking at compile time
   (dynamically typed -- ~greet~ has no declared type), no separate
   build artifacts (~.class~ / ~.jar~) -- everything stays a ~.py~ file --
   and it is much slower.
   #+end_quote

5) In the practice exercise you added ~setGreeting~ to =Greeting=. What
   kind of method is it, and what are its modifiers and return type?
   #+begin_quote
   A mutator (setter). It is ~public~ (so the test client can call it),
   returns ~void~ (like ~main~), and takes one ~String~ argument that it
   assigns to the private ~greeting~ field.
   #+end_quote

6) ~setGreeting~ and the constructor have almost the same body. What is
   the essential difference -- and why does renaming the class break
   the constructor?
   #+begin_quote
   When the constructor runs there is no object yet -- it is building
   one. When ~setGreeting~ runs there is already an object, and the call
   must name it (~greet.setGreeting("today mate")~). A constructor must
   also have exactly the class's name; once the class is renamed, the
   old constructor header is just an ordinary method with no return
   type, so it no longer parses as a constructor.
   #+end_quote

7) What does a Java ~interface~ declare, what does it *not* contain, and
   what does ~implements~ let you do at the call site?
   #+begin_quote
   An ~interface~ declares a contract: one or more method signatures
   (return type, name, parameters) with no bodies -- no
   implementation. Any class that ~implements~ it can then be held
   through the interface type instead of its concrete type, so a
   variable or array of the interface type can hold any implementing
   object.
   #+end_quote

8) In ~for (Greeter g : greeters) System.out.println(g.sayHello());~,
   which ~sayHello~ runs, and when is that decided? Name the mechanism.
   #+begin_quote
   Whichever ~sayHello~ belongs to the object's *real* class
   (~FormalGreeter~ or ~CasualGreeter~), decided at run time from the
   actual object -- not at compile time from the declared type
   ~Greeter~. This is *polymorphism*, implemented in Java as *dynamic
   dispatch*.
   #+end_quote

9) What is the payoff of writing =GreeterTest= against the ~Greeter~
   interface, and how does this preview the data structures later in
   the course?
   #+begin_quote
   The loop names no concrete class, so code written against the
   interface keeps working when you add another ~Greeter~ later, and the
   two greeter classes need no knowledge of each other. Same mechanism
   ahead: ~Stack~ and ~Queue~ will ~implement~ ~Iterable~ (one method,
   ~iterator()~), so ~for (String s : stack)~ works whether the stack is
   an array or a linked list underneath. (This course uses interfaces,
   not ~extends~ or abstract classes.)
   #+end_quote

10) Why delete the old ~.class~ files before recompiling, and what does
    the ~2>&1~ after ~javac~ do?
    #+begin_quote
    Delete them because ~.class~ files are rebuilt on every compile; a
    stale one left on the path can be picked up instead of your edited
    source, so ~rm -rf *.class~ forces a clean rebuild. ~2>&1~ sends
    standard error into standard output, so ~javac~'s errors show up in
    the same stream you are reading -- needed when that stream is
    captured (a notebook) rather than shown live in a terminal.
    #+end_quote

** Review - The performance challenge

1) What makes programming challenging?
   #+begin_quote
   Problems grow with input size. They may outgrow our processing
   capabilities: the program simply does not finish (in time).
   #+end_quote
2) What is the scientific method?
   #+begin_quote
   1. *Observe* reality (take *data*).
   2. Make an *assumption* about what's going on (*hypothesize*).
   3. *Predict* new events based on your assumption.
   4. *Check* your predictions with more data (experiment)
   5. *Modify* your assumption until you assume correctly.
   #+end_quote
3) How could you apply the scientific method to the weather?
   #+begin_quote
   1. You *observe* dark clouds in the sky.
   2. You *assume* it's going to rain.
   3. You *predict* rain in an hour.
   4. After an hour, you *check* if it's raining.
   5. If it isn't raining, you look for more weather *features*
      (pressure, wind, season) until you can better predict the
      weather.
   #+end_quote
4) What are the two conditions for the scientific method to work?
   #+begin_quote
   1. Your data must be *reproducible*. One-offs are useless.

      Weather example: focus on features that repeat

   2. Your assumptions must be *falsifiable*.

      Weather: if you assume that it rains when your nose itches, and
      then it does not rain when your nose itches, means that you
      falsified your assumption.
   #+end_quote
5) Why do we bother with the scientific method in programming?
   #+begin_quote
   - To *predict* program behavior -> will it finish?
   - To *compare* implementations -> will this make it better?
   - To *develop* new algorithms -> solve bigger problems
   #+end_quote

** How to read, how to study, how to learn programming

I'm going to make a video on this, I think, because it's important:

1) You don't learn by *grazing* (like a cow eat grass)

2) You don't learn by *gorging* (like a shark)

3) You don't learn by *gallivanting* (like a tourist)

4) You only learn by *grappling* with the material (like a wrestler)

5) How does one immerse oneself deeply (in CS)?
   #+begin_quote
   - Read the same passage (or code) again and again until it makes
     sense to you (or until you understand why it does not make sense)
   - Practice in small daily doses rather than cramming once a week --
   - Write code every day, even for ten minutes, the way you'd practice an instrument.
   - Struggle with a problem for a while before looking  up (or asking AI for) the answer: the friction is where the   learning happens, not the solution itself.
   - Produce, don't just consume -- reading someone else's code or
     watching a video feels like progress but doesn't build the same
     muscle as typing it yourself, breaking it, and fixing it.
   - Explain what you wrote to someone else, or out loud to yourself,
     or to the AI: if you can't explain it, you haven't actually
     learned it yet, no matter how cleanly it compiles.
   #+end_quote

** Review

1. What is =ThreeSum= supposed to give us?
   #+begin_quote
   Given =N= integers, =ThreeSum= gives us the number of triples (x,y,z)
   that add up to zero: x + y + z = 0.
   #+end_quote

2. How many triples can we pick from a set of N integers?
   #+begin_quote
   Looping i,j,k unrestricted over 0..N-1 gives N^3 = N * N * N index
   triples -- not permutations, since most of them have repeated
   indices (i=j, i=k, j=k) that don't pick 3 distinct elements at all.

   Of those, only N(N-1)(N-2) have three distinct indices -- that's
   the actual permutation count. Restricting further to i < j < k
   (one fixed ordering per underlying triple) gives C(N,3) =
   N(N-1)(N-2)/6 \approx N^{3}/6 unordered triples (combinations).
   #+end_quote

3. What does "brute-force" method mean? Example?
   #+begin_quote
   Try every possibility, with no cleverness to skip work. For
   example, brute-force =ThreeSum= loops N^3 index triples total. Only
   N(N-1)(N-2) of those have three distinct indices, and each of the
   C(N,3) real combinations shows up 3!=6 times among them -- the rest
   (i=j, i=k, j=k) are wasted iterations on repeated indices, not
   overcounted triples. Restricting to i < j < k fixes both problems
   at once (N^3 -> C(N,3)).

   Our other example: =Duplicates= (checking if a[i]==a[j]). Instead of
   brute-force pairwise comparison (N^{2}) sort first and scan adjacent
   elements once (sorting costs N log N -> next week).
   #+end_quote

** Solution to the trace problem for =ThreeSum= (from Wednesday)

#+begin_src java :dir src :tangle ../src/ThreeSumTrace.java :noeval :cmpflag "-cp .:stdlib.jar" :cmdline "-cp .:stdlib.jar"
  public class ThreeSumTrace
  {
      public static int countTriples(int[] a)
      {
          int n = a.length;
          int count = 0;
          // print header
          StdOut.println(" i  j  k   a[i]   a[j]   a[k]");
          for (int i = 0; i < n; i++)
              for (int j = i+1; j < n; j++)
                  for (int k = j+1; k < n; k++)
                      {
                          // store boolean if triple sum is zero
                          boolean hit = (a[i] + a[j] + a[k] == 0);
                          // print format string
                          StdOut.printf("%2d %2d %2d %6d %6d %6d%s\n",
                                        i, j, k, a[i], a[j], a[k],
                                        // evaluate using ternary operator:
                                        // `condition ? valueIfTrue : valueIfFalse
                                        hit ? "   <- sums to 0" : "");
                          // increase counter for hit
                          if (hit) count++;
                      }
          return count;
      }

      public static void main(String[] args)
      {
          int[] a = StdIn.readAllInts();
          int n = a.length;
          int count = countTriples(a);
          long rows = (long) n * (n - 1) * (n - 2) / 6;
          StdOut.println();
          StdOut.printf("rows printed:         %d%n", rows);
          StdOut.printf("C(%d,3) = %d! / (3! (%d-3)!) = %d%n", n, n, n, rows);
          StdOut.printf("triples summing to 0: %d%n", count);

      }
  }
#+end_src

*** Nesting =Stopwatch=: ~static~, ~public~ and ~verbose~

- Why does a nested =Stopwatch= need =static=?
  #+begin_quote
  Without ~static~, each =Stopwatch= secretly holds a pointer to a
  specific =HarmonicTiming= object - like a room that only exists within
  a particular house (the namespace of =HarmonicTiming=).

  ~main~ is ~static~ so when it runs, there is no =HarmonicTiming= object -
  there is no house to build the room (=Stopwatch=) in:

  =new Stopwatch= fails with ~non-static variable `this` cannot be
  referenced from a static context.~

  With ~static~, =Stopwatch= belongs to no object. It's an ordinary class
  that happens to be inside =HarmonicTiming= for tidiness. =new Stopwatch=
  works anywhere.

  *Rule: if the nested class does not need the outer object, make it
  ~static~.*
  #+end_quote

- Do you also need ~public~ for =Stopwatch=?
  #+begin_quote
  No. ~static class Stopwatch~ is enough, because only =HarmonicTiming=
  uses it. ~private static class Stopwatch~ works too. Only a top-level
  ~public~ class has to match the file name.
  #+end_quote

- Could you make it ~private~?
  #+begin_quote
  Yes, because it is only used in ~main~, and ~main~ sits inside
  =HarmonicTiming=.
  #+end_quote

- Do you have to nest it at all?
  #+begin_quote
  No. A second top-level class in the same file works, without ~static~,
  as long as it is not ~public~: one file can have only one ~public~
  class, and its name must match the file name.
  #+end_quote

- What makes a constructor?
  #+begin_quote
  The name of the class, and no return type. ~public Stopwatch() {...}~
  is a constructor and runs on ~new Stopwatch()~. ~public void
  Stopwatch()~ is an ordinary method that merely has the class's name -
  ~new~ never calls it but there is also no warning or error message!
  #+end_quote

- What if the class is missing from your file?
  #+begin_quote
  ~new Stopwatch()~ can still compile if another =Stopwatch= is on the
  class path - and =stdlib.jar= contains one. To see which class you
  get, compile without the jar (use ~System.out~ instead of ~StdOut~), or
  ask the compiler: ~javac -cp .:stdlib.jar -verbose HarmonicTiming.java~
  prints
  1) =[loading stdlib.jar(/Stopwatch.class)]= if ~stdlib.jar~'s file is
     loaded
  2) =[wrote HarmonicTiming$Stopwatch.class]= if the nested class is loaded.
  #+end_quote

*** Catching the crash: ~try~ and ~catch~ about?

- What's ~try~ and ~catch~ about?
  #+begin_quote
  Several of you had this idiom in their code.

  It's called EAFP: "Easier to Ask Forgiveness than Permission".

  It's opposite is LBYL: "Look Before You Leap".
  #+end_quote

- Well known in Python (they got it from C++):
  #+begin_src python :results output :exports both :session *Python* :python python3
    s = "hello"

    # LBYL: check first
    if s.isdigit():
        n = int(s)
    else:
        print("Not a number!")

    # EAFP: try, then handle the failure
    try:
        n = int(s)
    except ValueError as e:
        print(f"Not a number: {e}!")
  #+end_src

  #+RESULTS:
  : Not a number!
  : Not a number: invalid literal for int() with base 10: 'hello'!

- What do ~try~ and ~catch~ do?
  #+begin_quote
  The code in the ~try~ block runs normally. If it throws an exception
  of the type named in the ~catch~, Java skips the rest of the ~try~
  block, runs the ~catch~ block instead, and then the program carries on
  after it.
  #+end_quote

- What is the simplest example?
  #+begin_quote
  #+begin_src java :results output
    public class TryCatch {
        public static void main(String[] args) {
            try {
                int n = Integer.parseInt("hello");   // throws NumberFormatException
                System.out.println("n = " + n);    // skipped
            } catch (NumberFormatException e) {
                System.out.println("Not a number!");
            }
            System.out.println("Program continues.");
        }
    }
  #+end_src

  #+RESULTS:
  : Not a number!
  : Program continues.

  Without the ~try / catch~ the program ends at ~parseInt~ with
  ~Exception in thread "main" java.lang.NumberFormatException~ and never
  prints "Program continues."
  #+end_quote

- Which type does the ~catch~ need for the ~StackOverflowError~?
  #+begin_quote
  A ~catch~ matches by type. ~NumberFormatException~ is an ~Exception~.
  ~StackOverflowError~ is an ~Error~ - a =catch (Exception e)= would not
  catch it, but =catch (StackOverflowError e)= does.
  #+end_quote

- What's the difference between an exception and an error?
  #+begin_quote
  An *exception* signals a problem the program can be expected to handle
  (like bad input or a missing file). An *error* means that the JVM
  itself is in trouble because the stack is full.
  #+end_quote

- Did the assignment ask for it?
  #+begin_quote
  No. The crash was expected. Catching it just lets the program go on
  to the next =n= instead of ending. There's a chance you never see the
  recursion failing at all.
  #+end_quote

** Review: Friday (running experiments)

1. What does =RandomInts= print, and what do its two arguments control?
   #+begin_quote
   It prints =N= integers, one per line, uniformly distributed in
   [-M,M): every value is equally likely, -M is possible, M is not. =M=
   (first argument) sets the range of the values; =N= (second argument)
   sets how many are printed.
   #+end_quote

2. In the =smallR.txt= / =largeR.txt= experiment, why did we keep =N=
   fixed at 1000 and only change =M=?
   #+begin_quote
   Because then the range is the only difference between the two runs:
   any difference in the result can only be caused by the range, not
   by the input size. Next we do the opposite - fixed range, varying
   =N= - to find the timing behavior (the doubling hypothesis).
   #+end_quote

3. The number of three-sums that =ThreeSum= found differed by a factor
   of about 1000 between the small and the large range, but the
   running time was almost the same. Why?
   #+begin_quote
   The range changes /how many/ triples happen to sum to zero (the
   chance of finding one goes down with 1/R). It does not change /how
   many/ triples =ThreeSum= has to check: that is C(N,3) \approx
   N^{3}/6 in both runs. Both runs do the same amount of work, so we
   don't expect a difference in the timing.
   #+end_quote

4. What is the difference between ~real~, ~user~ and ~sys~ time, and how can
   ~user~ be larger than ~real~?
   #+begin_quote
   - ~real~: wall-clock time, from start to finish.
   - ~user~: CPU time spent in your program's own code.
   - ~sys~: CPU time the kernel spent on the program's behalf (system
     calls, I/O, memory allocation).

   ~user~ adds up CPU time over all threads and cores, so it can exceed
   ~real~ when the JVM runs several threads at once.
   #+end_quote

5. What does ~time~ write to, and how can you find out more about it?
   #+begin_quote
   ~time~ writes to ~stderr~ (standard error), not to standard output -
   that is why its output shows up separately from the program's output.
   To find out more, read its manual page (~man time~ on Linux and MacOS).
   #+end_quote
